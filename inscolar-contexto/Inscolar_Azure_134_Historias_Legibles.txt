Inscolar Historias de Azure en formato legible
----------------------------------------------

Fuente: exportación data.csv facilitada por el equipo, 29 de septiembre de 2026. Clave única: ID de Azure; HU020 aparece dos veces con alcances diferentes.

Contenido: 134 historias activas. Para 89 se reproduce la descripción y los criterios de la exportación (el HTML se convierte a texto). Para 45 con el campo Acceptance Criteria vacío se usa la propuesta revisada por el equipo en Inscolar_Historias_Azure_Pendientes.md, incluida la decisión sobre archivos, citas, inactividad, calificaciones y auditoría. Las seis historias Removed se excluyen al final.

Uso para el agente: busca por ID 347 o HU019. Lee únicamente las historias de la fase actual y compáralas con el plan. La política común de auditoría y las reglas transversales están en el documento de 45 historias; al implementar HU114–HU132 lee también esa sección. El texto no demuestra que una capacidad exista en el frontend.

HU015 · ID 343 · Modificar un usuario
-------------------------------------

Origen: Exportación de Azure: contenido existente; validar contra el work item vigente antes de editar.

Descripción
-----------

Yo Como: Administrador del sistema o usuario de soporte.

Quiero: Modificar la información de la cuenta de un usuario.

Para que: Pueda corregir datos incorrectos o la institución asignada a un usuario.

Desarrollo de la Historia
-------------------------

Elementos visuales
------------------

- Formulario con los datos del usuario seleccionado.

Campos
------

- Nombre completo (Texto)
  - Obligatorio.
  - Mínimo 3 caracteres.
  - Máximo 150 caracteres.
  - Solo permite letras, espacios, apóstrofes y guiones.

- Correo electrónico (Correo electrónico)
  - Obligatorio.
  - Máximo 254 caracteres.
  - Debe cumplir con un formato de correo válido.
  - Debe ser único dentro del sistema.

- Institución asignada (Lista desplegable)
  - Obligatorio para usuarios de tipo Personal de institución educativa.
  - No aplica para Administradores del sistema y Usuarios de soporte o tutores.

Botones
-------

- Guardar cambios: Al seleccionarlo, el sistema validará los datos ingresados y almacenará los cambios realizados.

- Cancelar: Al seleccionarlo, descartará los cambios no guardados y regresará a la pantalla anterior.

Funciones
---------

- El sistema debe validar que el correo electrónico no esté siendo utilizado por otro usuario cuando este sea modificado.

- El sistema debe mostrar la información actual del usuario seleccionado al ingresar a la pantalla de edición.

Reglas de negocio
-----------------

- Un Administrador del sistema puede modificar la información de cualquier usuario registrado en la plataforma.

- Un Usuario de soporte únicamente puede modificar usuarios cuyo rol sea:

- Personal de institución educativa.

- Tutor.

- Un Usuario de soporte no puede modificar cuentas de Administradores del sistema.

- Un Usuario de soporte no puede modificar cuentas de otros Usuarios de soporte.

- El sistema no permitirá guardar cambios si existen errores de validación o campos obligatorios vacíos.

Elementos conversación
----------------------

No hay elementos de conversación.

Anexos
------

No hay anexos.

Criterios de aceptación
-----------------------

*  El sistema deberá mostrar la información actual del usuario seleccionado al acceder a la pantalla de edición.

*  El Administrador del sistema podrá editar cualquier usuario registrado en la plataforma.

*  El Usuario de soporte solo podrá editar usuarios de tipo Personal de institución educativa o Tutor.

*  Si un Usuario de soporte intenta editar un Administrador del sistema o un Usuario de soporte, el sistema deberá impedir la acción y mostrar un mensaje de permisos insuficientes.

*  El campo Correo electrónico deberá cumplir con el formato válido de correo electrónico.

*  Si el correo electrónico ingresado ya pertenece a otro usuario, el sistema mostrará un mensaje de validación y no permitirá guardar los cambios.

*  Los campos obligatorios no podrán quedar vacíos.

*  Al seleccionar Guardar cambios, el sistema almacenará la información actualizada y mostrará un mensaje de confirmación.

*  Al seleccionar Cancelar, el sistema descartará los cambios realizados y regresará a la pantalla anterior.

*  Una vez guardados los cambios, el sistema deberá mostrar la información actualizada en futuras consultas del usuario.
